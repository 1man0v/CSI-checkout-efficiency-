# Требования к продукту

Каталог `requirements/` содержит исходные требования и является главным входом для Product Compiler.

## Организация файлов

Каждая тематическая папка должна сохраняться в структуре:

- `01-base/` — цель продукта, аудитория, контекст и границы;
- `02-system/` — функции, сущности, роли и бизнес-правила;
- `03-architecture/` — обязательные технические ограничения;
- `04-quality/` — нефункциональные требования;
- `05-integrations/` — внешние системы и обмен данными;
- `06-system-scenarios/` — технические и операционные сценарии;
- `07-scenarios/` — пользовательские и бизнес-сценарии.

Внутри каждой папки:

- не создавайте `README.md`;
- создавайте один или несколько `.md`-файлов;
- называйте файлы по содержанию и здравому смыслу;
- при необходимости разделяйте большую тему на несколько файлов;
- не дублируйте одну и ту же информацию в разных файлах.

ИИ обязан рекурсивно прочитать все файлы во всех папках `requirements/`. Наличие нескольких файлов в одном разделе не мешает обработке.

## Как фиксировать неизвестные решения

Если конкретного бизнес-решения пока нет, зафиксируйте вопрос непосредственно в тематическом файле:

```md
## NEEDS_INPUT: <краткое название>

Статус: NEEDS_INPUT

Вопрос: <какое решение требуется>

Контекст: <что уже известно>

Почему это важно: <что зависит от ответа>
```

Не нужно создавать отдельный файл на каждый вопрос и не нужно ставить статус на всю папку. В одном файле может быть несколько блоков `NEEDS_INPUT`.

## Кто закрывает NEEDS_INPUT

1. Product Manager или клиент принимает бизнес-решение.
2. ИИ-инструмент, выполняющий текущий этап, вносит полученный ответ в исходный файл требований и удаляет либо заменяет соответствующий блок `NEEDS_INPUT`.
3. Product Manager проверяет внесенное изменение.
4. Текущий этап запускается или продолжается только после закрытия вопросов, которые на него влияют.

ИИ не должен заменять отсутствующий ответ профессиональным допущением.

## Когда переходить дальше

Можно начинать этапы из `docs/`, даже если в требованиях остались вопросы, не влияющие на текущий этап. Перед каждым этапом ИИ самостоятельно проверяет все `NEEDS_INPUT` и определяет их влияние на создаваемый результат. Влияющие вопросы должны быть закрыты через диалог до продолжения этапа.
