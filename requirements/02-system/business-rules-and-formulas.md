# Бизнес-правила и формулы расчета метрик

Источник: Confluence 6381666307, 6323437618, 6133710853.

## Бизнес KPI MVP

| KPI | Цель |
| --- | --- |
| Доля чеков SCO | Рост с 20% до 28% |
| Доступность SCO | > 90% |
| Утилизация SCO | Рост по сети |
| Количество магазинов-аутсайдеров | Снижение |
| Потенциальные чеки SCO | Снижение объема чеков на POS |

## Верхнеуровневые нормативы (главный дашборд)

- **Доступность КСО.** Норматив: > 90%. Расчет: (время, когда КСО были доступны для покупки / время работы магазина) × 100%. Авто-норматив (если не задан вручную): медиана по аналогичным форматам (или сети) магазинов за весь доступный период.
- **Доля чеков КСО.** Норматив: > 30%. Расчет: (количество чеков на SCO / количество чеков на POS) × 100%. Авто-норматив — аналогично медиане по формату/сети.

## Формулы бизнес-показателей для суточных агрегатов

### 1. Доступность SCO

```
доступность = длительность доступности / длительность в чеке × 100
```

### 2. Утилизация SCO

```
утилизация SCO = длительность в продаже / длительность доступности × 100
```

### 3. Утилизация POS

```
утилизация POS = длительность в продаже / длительность смены × 100
```

### 4. Доля чеков SCO

```
доля SCO = чеки, зарегистрированные на SCO / все чеки магазина × 100
```

### 5. Потенциал SCO

Определение потенциального SCO-чека на POS: количество товаров в чеке ≤ 10 и тип оплаты ≠ наличные.

```
потенциальные SCO-чеки = количество чеков POS, удовлетворяющих условию выше
```

### 6. Упущенная эффективность

```
упущенная эффективность = потенциальные SCO-чеки − доля чеков SCO
```

### 7. Недоступность SCO

Определяется по идентификатору состояния SCO (см. «Состояния SCO» в `entities-and-data-dictionary.md`) и длительности нахождения в этом состоянии.

## Пороговые значения утилизации POS/SCO (по нормативу из кейса)

- SCO: норматив нагрузки — 1800 чеков/нед. Если факт < 1800 — индикатор «недогружены» (синий).
- POS: норматив нагрузки — 2000 чеков/нед. Если факт > 2500 — «перегруз» (риск очередей); если факт < 1500 — «избыток персонала».

## Цветовая индикация отклонений

- Производительность касс (p95, отклонение от норматива): до 15% — зеленый; 16–70% — желтый; ≥70% — красный.
- Доступность SCO (KPI-плашки): до 15% — красный; 16–70% — желтый; ≥70% — зеленый.

Примечание: направление шкалы цветов различается между блоками «Производительность» (рост отклонения — хуже) и «Доступность» (рост показателя — лучше); при реализации использовать логику соответствующего блока, а не единый обратный порог.

## Технический фактор недоступности (примеры аномалий и решений)

- **Нет бумаги** — простой выше медианы по сети → работа с дисциплиной персонала.
- **Ошибка банка** — простой выше медианы по сети → заявка в ИТ-отдел/банк-эквайер.
- **Заблокировано сотрудником** — простой выше медианы по сети → работа с дисциплиной персонала.
- Другие технические причины — см. ссылку в исходном документе Confluence (страница 5715099678, за пределами дерева данной задачи — не загружена в этот файл).

## Бизнес-фактор (эффективность и нагрузка)

- **Проверка доступности КСО** — аномалия при доступности ниже медианы по сети → работа с дисциплиной персонала.
- **Проверка утилизации ресурсов** — нагрузка SCO/POS относительно нормативов (см. пороги выше).
