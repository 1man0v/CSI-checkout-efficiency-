# 05. Создание карты функций

## Работа с NEEDS_INPUT

Перед запуском этапа ИИ рекурсивно проверяет все файлы в `requirements/`. Если незакрытый `NEEDS_INPUT` влияет на результат этапа, ИИ не принимает решение самостоятельно: формирует вопросы в `ai-artifacts/needs-input.md`, задает их Product Manager или клиенту и останавливает этап. После ответа ИИ обновляет исходный файл требований, а Product Manager подтверждает изменение. Только затем этап продолжается.


## Цель этапа

На этом этапе утвержденные артефакты Product Compiler преобразуются в карту небольших независимых функций для последующей реализации через Feature SDD.

Результат этапа:

```text
Approved Feature Map
```

## Входные данные

```text
Approved Product Model
Approved Screen Model
Approved Visual Prototype
Approved Prototype
```

## Запуск этапа

```text
Прочитай:

ai-artifacts/prompts/05-build-feature-map.md

и выполни инструкции из этого файла.
```

## Что выполняется на этапе

1. Разбить продукт на небольшие вертикальные функции, каждая из которых дает самостоятельную пользовательскую ценность.
2. Для каждой функции определить цель, границы, роли, зависимости и критерии приемки.
3. Сохранить трассируемость до требований, Product Model, Screen Model, визуального прототипа и сценариев прототипа.
4. Отделить подтвержденное поведение продукта от упрощений прототипа.
5. Зафиксировать продуктовые блокеры и нерешенные вопросы.
6. Не создавать техническую архитектуру, задачи реализации или production-код.

## Создаваемый артефакт

```text
ai-artifacts/08-feature-map.md
```

## Обязательная проверка

Проверьте, что:

- нет функции уровня «реализовать весь продукт»;
- каждая функция имеет самостоятельную ценность и четкие границы;
- зависимости между функциями указаны явно;
- критерии приемки сформулированы на продуктовом уровне;
- прототипные упрощения не выданы за требования production-системы;
- отсутствуют нерешенные продуктовые блокеры.

Если есть продуктовые блокеры, этап получает статус:

```text
NEEDS_INPUT
```

После подтверждения фиксируется статус:

```text
Approved Feature Map
```

## Что происходит дальше

После утверждения карты функций подготавливается пакет передачи в GitHub Spec Kit.
