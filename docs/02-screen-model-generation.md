# 02. Создание модели экранов

## Работа с NEEDS_INPUT

Перед запуском этапа ИИ рекурсивно проверяет все файлы в `requirements/`. Если незакрытый `NEEDS_INPUT` влияет на результат этапа, ИИ не принимает решение самостоятельно: формирует вопросы в `ai-artifacts/needs-input.md`, задает их Product Manager или клиенту и останавливает этап. После ответа ИИ обновляет исходный файл требований, а Product Manager подтверждает изменение. Только затем этап продолжается.


## Цель этапа

На этом этапе утвержденная модель продукта преобразуется в модель экранов.

Модель экранов отвечает на вопросы:

* какие экраны нужны пользователям;
* какие сценарии выполняются на каждом экране;
* какие действия доступны пользователю;
* как экраны связаны между собой.

Результатом этапа является утвержденная модель экранов:

```text
Approved Screen Model
```

---

## Входные данные

Для выполнения этапа нужна утвержденная модель продукта:

```text
Approved Product Model
```

Файл:

```text
ai-artifacts/01-product.model.json
```

---

## Запуск этапа

Откройте выбранный инструмент и передайте ему инструкцию:

```text
Прочитай:

ai-artifacts/prompts/02-build-screen-model.md

и выполни инструкции из этого файла.
```

---

## Что выполняется на этапе

Инструмент должен:

1. Прочитать утвержденную модель продукта.
2. Определить набор экранов.
3. Связать экраны с ролями, сущностями и бизнес-процессами.
4. Описать действия пользователя на каждом экране.
5. Описать состояния экранов.
6. Описать переходы между экранами.
7. Указать данные, необходимые каждому экрану.
8. Подготовить отчет для проверки.

---

## Создаваемые артефакты

### Модель экранов

Файл:

```text
ai-artifacts/02-screen.model.json
```

Содержит для каждого экрана:

* назначение;
* связанную сущность;
* пользовательские цели;
* действия;
* состояния;
* переходы;
* необходимые данные;
* предполагаемые существующие компоненты.

### Отчет о модели экранов

Файл:

```text
ai-artifacts/05-screen-model-report.md
```

Содержит:

* статистику экранов;
* найденные дубликаты;
* возможные пропуски;
* спорные решения;
* вопросы для проверки человеком.

---

## Обязательная проверка

После создания модели экранов нельзя переходить к следующему этапу без проверки человеком.

Проверьте:

* все ли основные сценарии покрыты экранами;
* нет ли дубликатов экранов;
* нет ли экранов без входящих или исходящих переходов;
* полна ли навигация;
* описаны ли основные действия пользователя;
* описаны ли состояния экранов;
* хватает ли экранов для создания, просмотра, изменения и удаления данных там, где это требуется.

---

## Результат этапа

Этап считается завершенным только после проверки модели экранов.

После подтверждения фиксируется статус:

```text
Approved Screen Model
```
