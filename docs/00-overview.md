# Product Compiler

Краткая карта процесса:

```text
Требования
      ↓
Модель продукта
      ↓
Модель экранов
      ↓
Визуальный прототип
      ↓
Прототип
      ↓
Карта функций
      ↓
Пакет передачи в GitHub Spec Kit
      ↓
Feature SDD
```

## Работа с NEEDS_INPUT

Перед запуском этапа ИИ рекурсивно проверяет все файлы в `requirements/`. Если незакрытый `NEEDS_INPUT` влияет на результат этапа, ИИ не принимает решение самостоятельно: формирует вопросы в `ai-artifacts/needs-input.md`, задает их Product Manager или клиенту и останавливает этап. После ответа ИИ обновляет исходный файл требований, а Product Manager подтверждает изменение. Только затем этап продолжается.


## Два уровня прототипирования

### Визуальный прототип

Кликабельный HTML-интерфейс, в котором работают навигация, переходы, формы, диалоги и состояния экранов. Он использует демонстрационные данные и не подключается к настоящему backend, API или базе данных. По желанию пользователя Figma может использоваться для чтения компонентов и макетов, генерации новых макетов и компонентов, а также последующей ручной доработки.

### Прототип

Работающее приложение, подключенное к backend, API и базе данных. Оно позволяет пройти ключевые сценарии с реалистичными, демонстрационными или согласованными клиентскими данными и может быть показано клиенту.

Прототип не является production-системой и не должен использоваться как финальный код продукта.

## Правила процесса

- Product Manager управляет переходами между этапами и при необходимости перезапускает процесс с нужного этапа;
- ИИ используется не только для создания артефактов, но и для их проверки;
- при обнаружении расхождений Product Manager возвращается к нужному этапу и повторно создает все зависимые артефакты;
- если проблема модели экранов обнаружена при создании визуального прототипа, процесс возвращается к этапу 02 без изменения самого процесса генерации модели экранов;
- все артефакты сохраняют связь с требованиями и продуктовой спецификацией;
- Product Compiler заканчивается передачей материалов в GitHub Spec Kit, а не генерацией production-кода.

Первый выполняемый этап:

```text
docs/01-product-model-generation.md
```

## Граница работы Product Manager

Product Manager последовательно выполняет этапы 01–04 и завершает основную работу созданием работающего прототипа. Прототип передается клиенту или пользователям для проверки. Если обратная связь меняет требования, Product Manager возвращается к затронутому этапу и повторно создает зависимые артефакты. Этапы 05–06 используются после согласования прототипа для подготовки решения к разработке.
