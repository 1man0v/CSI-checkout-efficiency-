## Пробелы в требованиях (Missing Requirements)

Ни одно обязательное Product Readiness Requirement не отсутствует. Ниже перечислены пробелы, которые не блокируют готовность модели продукта, но требуют закрытия на последующих этапах:

- Точные идентификаторы полей/событий в системе Set для показателей из `entities-and-data-dictionary.md` (маппинг схемы данных).
- Полнота перечня технических причин недоступности — исходная страница Confluence 5715099678 находится вне дерева требований и не была загружена.
- Статус и приоритет ИИ-консультанта и проактивного сценария (LFL-прогноз) в дорожной карте — подтверждено, что это надстройка вне MVP1/MVP2, но конкретный релиз не определен.
- Расшифровка аббревиатуры «ЦСЛ» и протокол интеграции (формат обмена, SLA).
- Механизмы аутентификации/авторизации и retry-политики для всех интеграций (касса → Kafka, DWH → ЦСЛ, Superset → Set Centrum).
- Маршрут эскалации задачи директора магазина (кому конкретно эскалируется просроченная/невыполненная задача) — в сценарии ДМ обозначен как «вероятно, РД», но не подтвержден явно.
- Точная периодичность оплаты подписки (ежемесячно/ежегодно) — тип объекта продажи, принцип цены и факт подписки подтверждены, конкретный интервал не уточнялся.
- Технический риск: возможность дублирования/потери чеков при смене master-кассы — требует проверки у архитекторов Set Retail, не у Product Manager.
- Точный подход к логированию платформы (конкретный лог-агрегатор Set Retail и способ подключения) — требует проверки у архитектора.
- Детальные характеристики серверного оборудования (CPU/RAM/диски) под каждый профиль сети — сайзинг по магазинам/кассам подтвержден, инженерный расчет ресурсов не выполнен (ожидаемо, задача следующего этапа — архитектуры).
