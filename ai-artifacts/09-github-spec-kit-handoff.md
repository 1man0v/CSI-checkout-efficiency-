# Пакет передачи в GitHub Spec Kit

Статус: **READY_FOR_GITHUB_SPEC_KIT**

Дата: 2026-10-19. Product Compiler на этом заканчивается. Дальше каждая функция из карты идёт отдельно через Feature SDD. Этот пакет не содержит архитектуру, технические задачи и production-код.

## Что передаётся

Продукт: **Set — Эффективность зоны расчета**. Лицензия по подписке, цена за число подключённых касс POS и КСО, поддержка входит в подписку. Поставка on-premise в контуре сети, релизом Set Retail 10.

Первая волна реализации — функции MVP1 из `ai-artifacts/08-feature-map.md`, в указанном там порядке. MVP2 и MVP3 на карте стоят как граница, не как работа текущего handoff.

## Решения Product Manager от 2026-10-19

1. ИИ-консультант — MVP3, после MVP2. На первых этапах собираются базовые метрики. Демо-диалог прототипа в MVP1 и MVP2 не переносится.
2. Страница «Другие технические причины» (Confluence 5715099678) в первый релиз не входит. Детализация — после MVP2, в MVP3. До этого действуют причины, уже названные в требованиях.
3. Все нормативы живут в настройках (SCR-08). Стартовые значения прототипа подтверждены, включая доступность POS 95%, порог «не в эксплуатации» 30 дней и скорость обслуживания без цветовой шкалы.

Точка входа — карта `ai-artifacts/08-feature-map.md`.

Для одной функции цикл такой:

1. Спецификация функции.
2. Разъяснение.
3. Технический план.
4. Задачи.
5. Реализация.
6. QA.

Нельзя собирать несколько независимых функций в один запрос на реализацию. Первыми идут F-01 и F-10: без агрегатов и настроек остальные экраны не на чем проверять.

## Поведение продукта и упрощения прототипа

Прототип доказывает сценарии. Он не является поставкой.

| В продукте | Только в прототипе |
| --- | --- |
| Kafka → POSDWH / DWH → ClickHouse → Superset → Set Centrum | `node:http`, `node:sqlite`, без внешних зависимостей |
| Роль определяется логином | Переключатель ролей |
| Метрики считаются из телеметрии | Готовые агрегаты и экспорт чеков за март 2026, 11 магазинов, 99 касс |
| Причина простоя привязана к кассе | Технические причины одним агрегатом на сеть |
| Доля КСО магазина считается из чеков | У №134 доля занижена до ~12,3% для демо диагноза |
| Нормативы читаются из SCR-08 | Доступность POS 95% зашита в `app.js` |
| Поставка релизом Set Retail, ru/en по ключам | Офлайн-HTML и локальный сервер на порту 4000 |

Формулу residual demand переносить как есть. Час может быть помечен избытком POS, хотя фактически открытая касса в этот час перегружена: формула отвечает, сколько POS нужно при переносе доступного потока на КСО. Разбор: магазин №375, 10:00, отчёт прототипа.

## Что решают инженеры

Продуктового ответа на эти пункты нет. Спецификация функции, которой пункт мешает, останавливается на нём, а не подставляет догадку.

- Идентификаторы полей в Set. Без них не закрыть схему события F-01. Файл: `requirements/02-system/entities-and-data-dictionary.md`.
- Расшифровка «ЦСЛ» и протокол выгрузки. Блокирует технический план F-12, не блокирует состав агрегата. Файл: `requirements/05-integrations/integrations.md`.
- Аутентификация, авторизация и повторы на границах касса → Kafka, DWH → ЦСЛ, Superset → Set Centrum. Тот же файл.
- Дубли или потеря чеков при смене master-кассы. Риск Set Retail, вне логики этого модуля. Файл: `requirements/06-system-scenarios/system-scenarios.md`.
- Какой лог-агрегатор Set Retail использовать для платформы. Тот же файл. Бизнес-мониторинг касс — функция продукта, не этот пункт.
- Версии Kafka, ClickHouse и Superset берутся из релиза Set Retail, отдельно не выбираются.
- Серверы под три профиля сети (до 100 / до 500 / от 500 магазинов) считаются от heartbeat раз в минуту. Числа CPU и дисков в требованиях нет.

## Риски, которые уже приняты

- Качество аналитики равно полноте телеметрии с касс.
- Нагрузка близкая к реальному времени на контур сети. SLA платформы 99%. Хранение телеметрии без срока, обрезка вручную инженером сервиса.
- Внедрение требует доработки касс, POSDWH, ClickHouse, Superset и дашбордов.
- Доступ сотрудников СЭТ — VPN с аудитом. Данные остаются в контуре сети.
- Дизайн-система «Set · Эффективность» в требованиях помечена черновиком и не является брендом Set.
