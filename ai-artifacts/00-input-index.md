## requirements/README.md

- **Назначение:** процессный документ — описывает структуру папки `requirements/`, конвенцию блоков `NEEDS_INPUT` и порядок их закрытия. Не содержит продуктовых требований.
- **Ключевые сущности:** —
- **Ключевые бизнес-процессы:** процесс закрытия `NEEDS_INPUT` (Product Manager принимает решение → ИИ обновляет исходный файл → Product Manager подтверждает).
- **Зависимости:** определяет правила для всех остальных файлов `requirements/`.
- **Уровень доверия:** высокий (процессные правила, не бизнес-факты).

## requirements/01-base/product-context.md

- **Назначение:** проблематика, бизнес-цели, целевая аудитория/роли, границы MVP1/MVP2, риски, коммерческая модель (объект продажи, цена, периодичность оплаты).
- **Ключевые сущности:** Магазин, Касса (POS/SCO/Touch/Hybrid), Лицензия/объект продажи.
- **Ключевые бизнес-процессы:** формирование единой аналитики для 6 ролей; переход MVP1 → MVP2.
- **Зависимости:** первоисточник для `02-system/*`, `03-architecture/*`, `04-quality/*`; коммерческая модель влияет на `salesObjects` модели продукта.
- **Уровень доверия:** высокий для проблематики/целей/MVP-границ (прямая выдержка из Confluence); высокий для коммерческой модели (подтверждено Product Manager 2026-07-20).

## requirements/02-system/system-requirements.md

- **Назначение:** обзорный документ, перечисляет 4 функциональных блока системы и верхнеуровневые KPI; отсылает к детализирующим файлам той же папки.
- **Ключевые сущности:** Касса, Чек.
- **Ключевые бизнес-процессы:** производительность касс, соотношение/потенциал SCO, доступность касс, утилизация ресурсов.
- **Зависимости:** агрегирует `user-roles-and-functional-blocks.md`, `entities-and-data-dictionary.md`, `business-rules-and-formulas.md`, `ai-advisor-concept.md`.
- **Уровень доверия:** высокий (прямая выдержка из Confluence).

## requirements/02-system/user-roles-and-functional-blocks.md

- **Назначение:** роли пользователей, их фокус/ценность, 4 функциональных блока с деталями сбора данных/формул/визуализации, матрица прав доступа по ролям.
- **Ключевые сущности:** Роль (ОД/РД/ДМ/технические службы/поддержка/продуктовые команды), Отчет, Норматив.
- **Ключевые бизнес-процессы:** анализ производительности POS/SCO, анализ потенциала SCO, анализ доступности, анализ утилизации; простановка/изменение нормативов по ролям.
- **Зависимости:** источник для `roles` и части `roleScenarios` модели продукта; связан с `entities-and-data-dictionary.md` (формулы используют те же данные).
- **Уровень доверия:** высокий для функциональных блоков (прямая выдержка из Confluence); высокий для матрицы прав и функций трех дополнительных ролей (подтверждено Product Manager 2026-07-20).

## requirements/02-system/entities-and-data-dictionary.md

- **Назначение:** словарь собираемых данных по 11 тематическим группам (чек, производительность, потоки, доступность, состояния SCO, утилизация, сотрудники, вызовы, отмены, финансовые метрики, суточные агрегаты).
- **Ключевые сущности:** Чек, Касса, Смена, Сотрудник, Вызов сотрудника, Состояние кассы.
- **Ключевые бизнес-процессы:** агрегация суточных показателей для отправки в ЦСЛ.
- **Зависимости:** используется всеми функциональными блоками `user-roles-and-functional-blocks.md` и формулами `business-rules-and-formulas.md`.
- **Уровень доверия:** средний — состав данных зафиксирован (высокий), но точные идентификаторы полей в системе Set не заполнены (открытый нефункциональный вопрос, не блокирует модель продукта).

## requirements/02-system/business-rules-and-formulas.md

- **Назначение:** формулы расчета метрик (доступность, утилизация, доля SCO, потенциал SCO, упущенная эффективность), пороговые значения нагрузки, цветовая индикация отклонений, типовые причины недоступности и рекомендации.
- **Ключевые сущности:** Норматив, Причина недоступности.
- **Ключевые бизнес-процессы:** расчет суточных агрегатов; классификация аномалий (технический/бизнес-фактор).
- **Зависимости:** опирается на `entities-and-data-dictionary.md`; используется в сценариях `07-scenarios/business-scenarios.md`.
- **Уровень доверия:** высокий для формул и порогов (прямая выдержка из Confluence); полнота списка технических причин недоступности не подтверждена (ссылка на страницу вне дерева требований).

## requirements/02-system/ai-advisor-concept.md

- **Назначение:** концепция надстройки — операционный ИИ-консультант (вопрос-ответ на естественном языке) и подтвержденный Product Manager проактивный сценарий (автопостановка задачи по LFL-прогнозу).
- **Ключевые сущности:** Расследование, Гипотеза, Рекомендация, Аналитический модуль (внутренний).
- **Ключевые бизнес-процессы:** маршрутизация вопроса → выбор расследования → запуск модулей → проверка гипотез → рекомендация → ответ; проактивная постановка задачи по прогнозу.
- **Зависимости:** опирается на аналитические модули, описанные в `user-roles-and-functional-blocks.md`; проактивный сценарий связан с NFR по задержке данных (`04-quality/quality-requirements.md`).
- **Уровень доверия:** высокий для описания механики (прямая выдержка из Confluence); низкий для статуса в дорожной карте — открытый вопрос, не входит в MVP1/MVP2, не блокирует текущий этап.

## requirements/03-architecture/technical-constraints.md

- **Назначение:** обязательный технологический стек (Kafka/POSDWH/ClickHouse/Superset/Set Centrum), правила хранения и агрегации данных, модель развертывания, версионирование, резидентность данных.
- **Ключевые сущности:** —
- **Ключевые бизнес-процессы:** сбор и агрегация телеметрии, отправка агрегатов в ЦСЛ.
- **Зависимости:** формирует раздел `integrations` и часть `infrastructureRequirements` модели продукта.
- **Уровень доверия:** высокий (стек — прямая выдержка из Confluence; модель развертывания и версионирование — подтверждены Product Manager 2026-07-20).

## requirements/04-quality/quality-requirements.md

- **Назначение:** нефункциональные требования — производительность/задержка, масштабируемость/отказоустойчивость, визуализация, хранение данных, доступ по ролям, локализация, сайзинг; референс на дизайн-систему (не утвержденное требование).
- **Ключевые сущности:** —
- **Ключевые бизнес-процессы:** проактивная постановка задачи ИИ-агентом (обоснование NFR по задержке).
- **Зависимости:** формирует `infrastructureRequirements` модели продукта; связан с `ai-advisor-concept.md`.
- **Уровень доверия:** высокий (числовые цели, сайзинг и локализация подтверждены Product Manager 2026-07-20).

## requirements/05-integrations/integrations.md

- **Назначение:** описание 6 внешних систем/компонентов интеграции (Kafka, POSDWH/DWH, ClickHouse, Superset, Set Centrum, ЦСЛ) — назначение и направление обмена данными.
- **Ключевые сущности:** —
- **Ключевые бизнес-процессы:** транспорт телеметрии, построение отчетов, встраивание дашбордов, экспорт агрегатов в ЦСЛ.
- **Зависимости:** напрямую формирует раздел `integrations` модели продукта.
- **Уровень доверия:** средний — назначение и направление обмена зафиксированы (высокий), но формат обмена, аутентификация и retry-политики не описаны (не блокирует модель продукта, влияет на дальнейшее архитектурное проектирование).

## requirements/06-system-scenarios/system-scenarios.md

- **Назначение:** мониторинг доступности кассы через heartbeat, реакция на аппаратные ошибки, порядок появления/выбытия магазинов и касс в отчетности, решение по синхронизации/кластеризации касс (out of scope), поставка/установка/обновление/логирование/мониторинг платформы.
- **Ключевые сущности:** Касса, Состояние кассы.
- **Ключевые бизнес-процессы:** heartbeat-мониторинг; автоматическое отражение выбытия/возврата кассы в отчетности.
- **Зависимости:** опирается на состояния кассы из `entities-and-data-dictionary.md`; формирует часть `deliveryAndOperations` модели продукта.
- **Уровень доверия:** высокий (все ключевые решения подтверждены Product Manager 2026-07-20); два открытых технических риска (дублирование чеков при смене master, точный лог-агрегатор) не блокируют модель, требуют проверки у архитекторов Set Retail.

## requirements/07-scenarios/business-scenarios.md

- **Назначение:** детальный пользовательский сценарий «Оптимизация нагрузки и ресурсов (POS vs SCO)» для ОД/РД (4 этапа), кейс «Магазин №404», сценарий директора магазина (получение/выполнение задачи).
- **Ключевые сущности:** Задача, Рекомендация, Норматив.
- **Ключевые бизнес-процессы:** верхнеуровневый мониторинг → поиск аутсайдеров → анализ причин → анализ потенциала КСО; получение и выполнение задачи ДМ.
- **Зависимости:** опирается на формулы `business-rules-and-formulas.md` и функциональные блоки `user-roles-and-functional-blocks.md`; напрямую формирует `roleScenarios` и часть `workflows`/`screens` модели продукта.
- **Уровень доверия:** высокий (сценарии ОД/РД — прямая выдержка из Confluence; сценарий ДМ — подтвержден Product Manager 2026-07-20; маршрут эскалации задачи не детализирован).
