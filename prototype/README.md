# Прототип: Set — Эффективность зоны расчета

Работающий прототип (frontend + backend + API + база данных) для этапа «Прототип» Product Compiler.
**Не production-система.** См. `ai-artifacts/07-prototype-report.md` за пределами этой папки для полного отчета,
включая доработку 2026-07-22 по 19 замечаниям к демонстрации (выбор периода с календарем-подсказкой,
кликабельные KPI с почасовыми графиками тренда/p95, история состояний касс, реалистичные задачи,
многоязычный переключатель, экспорт CSV и др.) и второй раунд доработки того же дня по 12 замечаниям
(единый формат дат dd.mm.yyyy и реальный выбор диапазона в календаре, сокращение языков до ru/en с полной
сверкой перевода, переделанный блок POS, сводная по регионам с ФИО региональных директоров, исправленный
баг сброса прокрутки при сортировке/фильтрах, переход с плашки «Магазинов на контроле» в задачи, широкие
графики drill-down), обновление 2026-09-13 — переход показателей нагрузки/доли SCO/потенциала SCO/
скорости обслуживания на реальный экспорт чеков сети за март 2026 (11 магазинов, 99 касс, ~751 тыс.
чеков), и обновление 2026-09-13 (раунд 2) — упрощение дашбордов ОД/РД/ДМ до двух ключевых показателей
+ таблицы аутсайдеров + задач наверху экрана (остальные метрики — под «Подробнее»), плюс блок «Диагноз
и рекомендация» на карточке магазина-аутсайдера. См. раздел «Данные» ниже и оба обновления в
`ai-artifacts/07-prototype-report.md`.

## Требования

- Node.js **22.5 или новее** (используется встроенный экспериментальный модуль `node:sqlite` — внешних зависимостей нет, `npm install` не требуется).

## Запуск

```bash
cd prototype
npm run seed   # создает/пересоздает SQLite-базу и заполняет демонстрационными данными
npm start      # запускает сервер на http://localhost:4000
```

Открыть в браузере:

- `http://localhost:4000/index.html` — основной продукт (все аналитические экраны, задачи, канбан, ИИ-консультант)
- `http://localhost:4000/settings.html` — отдельное приложение настроек (SCR-08)

## Сброс данных

```bash
npm run seed
```

Пересоздает файл БД (`backend/data/prototype.db`) с исходным демонстрационным набором данных (11 магазинов, кассы, задачи, нормативы). Любые изменения, сделанные через интерфейс (статусы задач, согласованные нормативы, заявки в ИТ), при этом стираются. Файл БД не хранится в git (см. `.gitignore` в корне репозитория) — он всегда воспроизводится посевом.

## Данные

Начиная с 2026-09-13 посев (`backend/seed.js`) считает часть показателей из реального экспорта чеков
сети за март 2026 (`backend/seed-data/real-transactions-2026-03.json` — компактный агрегат, посчитанный
одноразовым скриптом из сырого CSV/XLS-экспорта на ~763 тыс. строк; сам сырой файл в репозиторий не
включен из-за размера). Из реальных данных: номера 11 магазинов и 99 касс, доля чеков SCO, потенциал
SCO, нагрузка (чек/нед), средняя и p95 длительность чека по каждой кассе, суточные и почасовые ряды
чеков (в т.ч. форма графика «потоки по часам»). Синтетическим остается все, для чего в экспорте чеков
нет данных: название/регион/формат/ФИО директора магазина (заглушки до реального маппинга от
заказчика), доступность кассы (в чеках нет телеметрии простоя), текущий статус конкретной кассы
(no_paper/bank_error/офлайн и т.д. — экспорт историчен и не содержит "текущего" состояния
оборудования). Подробности и полный список допущений — в комментарии в шапке `backend/seed.js` и в
обновлении 2026-09-13 в `ai-artifacts/07-prototype-report.md`.

**Единственное намеренное искажение реальных чисел**: магазин №134 «Лесной» — доля чеков КСО занижена
с реальных 53.7% до ~12.3% (`SCO_SHARE_DEMO_OVERRIDE` в `seed.js`), чтобы было на чем показать блок
«Диагноз и рекомендация» для business-фактора (низкая доля КСО при нормальной доступности) — ни один
из 11 реальных магазинов такой кейс не показывает, реальная сеть уже везде выше норматива 30%.

**«Загрузка кассовой линии» (карточка магазина, 2026-09-13, раунд 5)** — отдельный файл
`backend/seed-data/hourly-capacity-2026-03.json` (число открытых касс и целевых для КСО чеков по
часам, посчитано вторым проходом по тому же сырому экспорту чеков) + `registers.avg_seconds` дают
пропускную способность касс по формуле "residual demand" — подробности в разделе «Обновление 2026-09-13
(раунд 5)» отчета.

Реальный экспорт покрывает только 30 дней (март 2026), а дашборды строят период относительно
"сейчас" — 30-дневный реальный цикл переигрывается дважды подряд, чтобы 60-дневное окно календаря не
пустовало (даты и часы работы дня совпадают с реальными, конкретный год/месяц — нет).

## Роли (демо)

Переключатель ролей в боковой панели (Операционный директор / Региональный директор / Директор магазина) — без реальной аутентификации, как и в `visual-prototype/`. Роль «Региональный директор» зафиксирована на регионе «Регион 3» (плейсхолдер), роль «Директор магазина» — на магазине «№134 «Лесной»» (обновлено 2026-09-13: демо-магазин с business-фактором и блоком «Диагноз и рекомендация» из двух рекомендаций — см. `DM_STORE_ID` в `app.js`).

## Структура

```text
prototype/
  package.json
  README.md
  backend/
    server.js       — HTTP-сервер (node:http, без Express) + REST API + статика фронтенда
    db.js           — подключение к SQLite (node:sqlite)
    schema.sql       — схема БД
    seed.js          — воспроизводимый посев демо-данных
    rules.js         — бизнес-правила (пороги KPI, доступность при офлайне, эскалация)
    routes/          — обработчики API по областям (магазины, задачи, настройки, причины/заявки, прочее)
    data/            — файл SQLite (не в git, создается посевом)
  frontend/
    index.html, settings.html, styles.css, i18n.js, api.js, app.js
```

## Ограничения (не переносить в production)

См. подробности и обоснование в `ai-artifacts/07-prototype-report.md`, раздел «Упрощения и известные ограничения». Кратко:

- `node:sqlite` — экспериментальный API Node.js, а не согласованная СУБД продукта.
- Сервер без Express/маршрутизатора — ручной роутинг по regex, приемлемо для объема прототипа, не для production API.
- Бизнес-показатели (доступность, доля SCO, утилизация) хранятся как готовые агрегаты, а не вычисляются из сырых событий телеметрии (Kafka/ClickHouse — вне периметра прототипа).
- Технические причины простоя — общий агрегат по сети, не разбиты по магазину/кассе.
- Нет аутентификации — переключатель ролей демонстрационный.
- Нет HTTPS, секретов, реальных персональных данных.
