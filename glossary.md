# Глоссарий

Заглушка для терминов, которые понадобятся конкретному продукту.

Product Manager должен:
- добавить только те термины, которые реально используются в проекте;
- удалить устаревшие и чужие названия;
- поддерживать согласованность терминологии во всех документах.

## Визуальный прототип

Утвержденный кликабельный интерфейс, сохраненный в Git. Содержит HTML с работающей навигацией и локальными взаимодействиями, но без настоящего backend, API, базы данных и реальных интеграций. При необходимости может создаваться или дорабатываться с использованием Figma.

## Прототип

Работающее приложение с frontend, backend, API и базой данных, предназначенное для демонстрации клиенту и проверки ключевых сценариев на реалистичных данных. Не является production-системой и не используется как финальный код продукта.

## GitHub Spec Kit Handoff

Пакет утвержденных продуктовых артефактов и карта функций, передаваемые программистам для последующей реализации через GitHub Spec Kit и Feature SDD.

## Feature Map

Карта небольших вертикальных функций продукта с пользовательской ценностью, границами, зависимостями, критериями приемки и трассируемостью.

## Перезапуск процесса

Если после проверки или демонстрации требуется изменение, Product Manager самостоятельно запускает Product Compiler повторно с нужного этапа. Отдельный обязательный этап пользовательской валидации в процессе отсутствует.

## NEEDS_INPUT

Явно зафиксированный вопрос, по которому требуется бизнес-решение Product Manager или клиента. Статус размещается непосредственно в тематическом файле требований. ИИ не имеет права заменять ответ допущением. Если вопрос влияет на текущий этап, ИИ собирает вопросы в `ai-artifacts/needs-input.md`, останавливает этап, а после ответа обновляет исходный файл требований под контролем Product Manager.
